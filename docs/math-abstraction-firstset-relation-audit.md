Status: derived relation audit.

## Purpose

This file reviews the 66 math-abstraction situations currently marked:

```text
Include in first math set = yes
```

This is intentionally separate from the raw situation inventory. The raw file
should remain observational. This file is where relation interpretation and
graph coverage checking belongs.

The goal is not to teach formal mathematics directly. The goal is to identify
compact, reusable relation families that can support later number, quantity,
ordering, grouping, measurement, pattern, symbol, logic, and abstraction.

## Selection Criteria

The first set was prioritised in `docs/math-abstraction-200-situations.md`
using:

```text
coverage of root abstraction relations
frequency in ordinary child and adult reasoning
usefulness for later language, science, and formal math
counterfactual usefulness for held-out evaluation
avoidance of overly narrow calendar, money, map, and chance examples in pass one
```

The selection is not final. It is a first executable math-abstraction slice.

## Summary

The existing child, physical, and social graphs already contain some roots that
math can build on:

```text
same/different perception
more/less comparison
inside/outside and on/under spatial relations
before/after sequence
blocked/unblocked path
one object versus many objects in ordinary scenes
repetition and expected/unexpected patterns
symbol or word binding precursor
```

But the math-abstraction curriculum needs these roots represented as explicit
abstraction-building schemas. The main missing or underdeveloped relation
families are:

```text
identity, difference, similarity, and odd-one-out
attribute-specific matching
zero, one, two, and many
one-to-one counting correspondence
counting errors such as skip and double count
add-one and remove-one quantity change
more/less/equal comparison
one-to-one distribution and leftover
ordered series, ordinal position, and ordered instructions
classification by property, function, and rule
negation and exclusion from a group
containment, fit, on/under, path, and blockage as abstract spatial schemas
part/whole composition and completion
measurement by alignment, repeated units, and gap errors
repeating pattern, missing pattern element, and next-item prediction
symbol-to-quantity and mark-to-count binding
simple data display and comparison
if/then, not, and/or, and reusable rule transfer
```

## Relation Families To Add

The following should become the first math-abstraction graph extension. Names
are proposed IDs, not final commitments.

### 1. Identity, Difference, and Attribute Matching

Needed for:

```text
M001 same red blocks
M002 red block and blue block
M004 round ball and square block
M005 matching sock
M006 odd sock
M016 another triangle
M017 one shape not like others
```

Proposed additions:

```text
invariant.same_different
schema.attribute_match
schema.attribute_contrast
schema.odd_one_out
schema.match_selection
property.matching_attribute
property.mismatching_attribute
```

This is the first root of abstraction: two items can be the same or different
with respect to a selected attribute, not necessarily the entire object.

### 2. Zero, One, Two, Counting, and Quantity Change

Needed for:

```text
M021 one biscuit
M022 two biscuits
M024 no biscuits versus some biscuits
M025 pointing while saying number words
M026 touching same toy twice
M027 skipping one toy
M031 one more toy added
M032 one toy removed
```

Proposed additions:

```text
invariant.zero_one_many
schema.object_count
schema.counting_correspondence
schema.double_count_error
schema.skip_count_error
schema.add_one_quantity_change
schema.remove_one_quantity_change
relation.binds_number_word_to_count
```

Counting should be modeled as correspondence between distinct counted items and
ordered count tokens, not as memorized number words alone.

### 3. More, Less, Equal, Distribution, and Leftover

Needed for:

```text
M041 more grapes
M042 same number of grapes
M046 one cup to each person
M047 two cups to one person and none to another
M048 shoe-foot pairing
M049 one shoe left
M054 one sweet to each child
M055 one child gets extra sweet
```

Proposed additions:

```text
invariant.more_less_equal
schema.quantity_comparison
schema.one_to_one_assignment
schema.pairing_correspondence
schema.unmatched_leftover
schema.unequal_distribution
schema.extra_item
```

This connects pure quantity to later social ideas such as fairness without
making fairness primitive in the math graph.

### 4. Order, Ordinal Position, and Step Sequence

Needed for:

```text
M066 smallest to largest
M067 largest to smallest
M068 shortest to longest
M070 first in line
M073 daily routine order
M079 swapped two-step instruction
M080 three-step instruction
```

Proposed additions:

```text
invariant.before_after
schema.ordered_series
schema.reverse_order
schema.ordinal_position
schema.event_sequence_order
schema.instruction_step_order
schema.order_violation
```

Ordering should work across size, length, line position, time, and instruction
steps.

### 5. Grouping, Classification, Rule Change, and Negation

Needed for:

```text
M086 all red objects
M087 all round objects
M088 red round versus red square objects
M089 spoons, forks, and plates
M096 can be worn versus cannot be worn
M100 sorting rule changes
M101 not red
```

Proposed additions:

```text
schema.property_grouping
schema.category_grouping
schema.function_grouping
schema.multi_attribute_filter
schema.sorting_rule
schema.rule_change
schema.negated_property_filter
relation.member_of_group
relation.excluded_from_group
```

This is where abstraction becomes explicit: a group is formed by a rule over
relations, and the rule can change.

### 6. Spatial Abstraction, Containment, Fit, and Path

Needed for:

```text

M107 large toy does not fit inside box
M108 ball under chair
M109 ball on top of chair
M113 arrow path
M114 blocked path
```

Proposed additions:

```text
invariant.inside_outside
invariant.on_under
invariant.path_blocked_unblocked
schema.containment_fit
schema.fit_failure
schema.spatial_position_relation
schema.path_following
schema.path_blockage
```

These are physical relations, but the math graph should reuse them as portable
spatial abstractions.

### 7. Part/Whole, Completion, and Measurement

Needed for:

```text
M119 two half-circles make a circle
M126 full and half-full glass
M127 same water in different glass shapes
M128 rope ends lined up
M130 hand spans measure table
M132 same block repeatedly measures shelf
M133 gaps while measuring
M135 heavy small stone and light large sponge
```

Proposed additions:

```text
invariant.part_whole
schema.shape_composition
schema.level_comparison
schema.quantity_conservation_candidate
schema.aligned_measurement_comparison
schema.repeated_unit_measurement
schema.measurement_gap_error
schema.cross_property_independence
```

This family prevents shallow shortcuts such as bigger-looking means more, or
larger object means heavier.

### 8. Pattern, Repetition, Missing Element, and Prediction

Needed for:

```text
M146 red-blue-red-blue beads
M147 red-blue-green repeated beads
M148 clap-clap-pause rhythm
M150 missing bead in a pattern
M160 next picture in repeated story sequence
```

Proposed additions:

```text
invariant.repeats
schema.alternating_pattern
schema.cyclic_pattern
schema.rhythm_pattern
schema.missing_pattern_element
schema.next_item_prediction
```

Patterns should be treated as repeated relation structures that support
prediction.

### 9. Symbol, Quantity Representation, and Simple Data

Needed for:

```text
M161 spoken three and written 3
M162 three dots and written 3
M168 tally marks for children entering
M169 bar chart of favorite fruits
```

Proposed additions:

```text
schema.number_symbol_binding
schema.quantity_symbol_mapping
schema.tally_event_count
schema.category_count_display
schema.bar_length_quantity_display
relation.symbol_represents_quantity
relation.mark_represents_event
```

This bridges math and language binding: the symbol is a handle into a relation
cluster, not the meaning itself.

### 10. Conditional, Logical Selection, and Rule Transfer

Needed for:

```text
M176 if shoes are wet, keep them outside
M177 if red light, stop
M179 not spicy
M180 red and soft
M181 red or soft
M200 same rule on new objects
```

Proposed additions:

```text
schema.conditional_action_rule
schema.signal_conditioned_action
schema.not_filter
schema.and_filter
schema.or_filter
schema.rule_transfer
relation.condition_triggers_action
relation.rule_applies_to_new_set
```

This is the core abstraction test: can the same rule operate over new objects
without memorizing the original scene?

## Proposed First Graph Shape

The first math graph should not be a formal math ontology. It should be a small
abstraction graph with these layers:

```text
layer.math_input
layer.math_invariant
layer.math_schema
layer.math_symbol
layer.math_event
layer.math_abstraction
```

Initial node families:

```text
invariants:
  same_different
  zero_one_many
```
