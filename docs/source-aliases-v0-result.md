## Interpretation

The approved aliases loaded correctly, but the existing source extractors did
not gain relation coverage.

This is not because the mappings are useless. It means the source-near terms
mostly appear in lexical source relations such as:

```text
DerivedFrom
FormOf
RelatedTo
Synonym
definition text
```

Examples:

```text
hiddenness DerivedFrom hidden
attachedness DerivedFrom attached
breakableness DerivedFrom breakable
visibleness DerivedFrom visible
safeness DerivedFrom safe
```

The current relation extractors intentionally keep only a narrow set of
ontology-like or visual relations:

```text
is_a
has_property
can_do
used_for
at_location
part_of
has_a
causes
receives_action
```

So aliases help only when a source phrase is an endpoint in one of those
accepted relation types. For many root concepts, the source only tells us a
lexical equivalence or derivation, not a usable object/action/property fact.

## Next Fix

Add a separate lexical binding layer:

```text
source phrase -> seed concept
```

Rendered as controlled language, for example:

```text
hiddenness means hidden.
attachedness means attached.
breakableness means breakable.
```

This should remain separate from external factual relations. It teaches the
model that the source vocabulary and our seed vocabulary refer to the same
handle, without pretending that a new world fact was discovered.
