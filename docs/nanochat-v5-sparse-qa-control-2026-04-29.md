# nanochat V5 Sparse QA Control

Date: 2026-04-29

## Purpose

Test whether the V5 5K result comes from relation-dense text or merely from
the answer protocol, object priors, and repeated generator distribution.

This control keeps the same source examples, train/dev/test split, prompt
types, targets, tokenizer, model shape, and token budget as the 5K 250-step
plain-QA run. It changes only the scene text.

## Dataset

Generated by:

```text
scripts/create_procedural_foundation_sparse_qa.py
```

Output:

```text
data/developmental_graph/experiments/procedural_foundation_v5_sparse_qa_5k/
```

Variant:

```text
word_sparse_qa
```

Counts:

```text
train: 5000
dev: 2765
curriculum_test: 3115
```

The sparse scene removes discriminating relation cues such as:

```text
near/far
open/closed
wet/dry
edge/middle
count
color
hot/cold
in hand/on floor
```

Example:

```text
Dense:  Scene: Toy is on table far from baby. Baby reaches hand.
Sparse: Scene: Baby is here. toy is here. baby moves hand.
Target: answer: no. reason: hand does not touch toy.
```

| --- | --- | ---: | ---: |
| dense plain QA | dense prompts | 82.2% (2561/3115) | 70.7% (2201/3115) |
| relation-output QA | dense prompts | 74.5% (2322/3115) | 55.8% (1738/3115) |

The sparse model still does not improve with more examples and more training.
It learns the sparse surface distribution well enough to lower BPB, but it
does not learn the missing relation distinctions needed for the held-out QA
task.

## Interpretation

This is a strong control result for the current hypothesis:

```text
The high V5 plain-QA result depends on relation-dense scene text.
```

The model does not get close to the 70-85% range when trained on sparse scenes.
This remains true both at 5K / 250 and at 22K / 1000 with the same answer
protocol, tokenizer, model shape, and evaluation set. It mostly falls back to
priors and answer-distribution guesses.

This supports the move to proper text only, but not arbitrary text. The text
must be generated from clean relation structure.
